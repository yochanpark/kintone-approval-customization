# Kintone 전자결재 커스터마이징

사내 전자결재를 **Kintone**으로 전환하면서 나온 요구를 받아
JavaScript 커스터마이징과 운영 개선으로 처리한 기록이다.

고객사 건이라 앱 정의·업무 데이터·공수 산정은 올리지 않는다.
**직접 작성한 코드와 그 설계 근거**만 담았다.

---

## 다룬 것

| 과제 | 해결 |
|---|---|
| **승인 후에도 기안자가 금액을 고칠 수 있었다** | 역할·상태 기반 편집 잠금 — [코드](src/requester-cannot-edit.js) · [설계](docs/01-edit-lock.md) |
| 앱별 검색 기능 부재 | 앱마다 지정 열 1개로 검색 — [기록](docs/02-search-and-ops.md) |
| 결재라인 반영 누락이 반복됨 | 권한 구조 정리와 매뉴얼 체계 — [기록](docs/02-search-and-ops.md) |
| RPA 산출 폴더가 과도하게 분기됨 | 업체별 1단계로 단순화 — [기록](docs/02-search-and-ops.md) |

가장 중요한 것은 첫 번째다. **승인이 끝난 문서의 금액을 기안자가 수정할 수 있다는 것은
내부통제 결함**이고, 그래서 UI만 가리는 방식으로는 부족했다.

---

## 식별정보

고객사·관계사·담당자 실명과 공수 산정(MD) 수치는 모두 제외했다.
코드에는 원래부터 고객 식별자가 없어 **원문 그대로**다.
