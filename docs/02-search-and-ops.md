# 2. 검색 기능과 운영 개선

편집 잠금 외에 같은 전환 과정에서 나온 요구들이다.
코드보다 **구조를 어떻게 정리했는지**가 내용이다.

## 앱별 검색 기능

결재 시스템을 Kintone으로 옮기고 나니 기존에 있던 검색이 사라졌다.
앱이 8개인데 전부 목록을 눈으로 훑어야 했다.

요구는 단순했다 — **앱마다 지정한 열 하나로 검색**.
앱 구조가 이미 있고 복합 조건이 없어서, 앱당 검색 대상 열을 하나 정하고
같은 패턴을 8개에 복제하는 방식으로 처리했다.

조건을 일반화해 하나의 검색 컴포넌트로 만들 수도 있었지만,
앱마다 열 이름과 타입이 달라 추상화 비용이 복제 비용보다 컸다.

## 결재라인 반영 누락

결재라인 변경이 잦은데 반영이 빠지는 일이 반복됐다.
예를 들어 사전결재의 잔업신청 카테고리에 결재라인이 들어가지 않았다.

원인은 **변경 요청과 반영 확인 사이에 검증 단계가 없다는 것**이었다.
바뀐 결재라인은 실제로 결재를 올려 보기 전에는 확인할 방법이 없어,
반영 뒤 수작업으로 반복 확인하는 시간이 계속 들었다.

정리한 방향:

- 프로세스 관리·승인 알람·권한·참조자 설정은 **모든 앱이 동일** → 공통 매뉴얼 1벌
- 업무 목적·기능·역할은 **앱마다 다름** → 앱별 매뉴얼은 별건
- 현업 담당자가 직접 세팅할 수 있는 범위를 정해 개발자 왕복을 줄임

앱마다 매뉴얼을 다 쓰는 것은 공수가 크고, 앱이 바뀔 때마다
담당자와 개발자가 설정을 이중으로 검토하게 되어 비효율이 남는다는 점을 같이 전달했다.

## 관리자 권한 분리

한 법인의 관리자가 다른 법인의 안건을 조회할 수 있는 상태였다.
관리 권한을 정리해 **법인별로 분리**했다.

앞 문서에 적은 대로 Kintone 관리자는 조회를 막을 수 없으므로,
"관리자에게 안 보이게" 가 아니라 **"관리자 자체를 나눈다"** 가 유일한 해법이다.

## RPA 산출 폴더 구조

RPA가 결과 파일을 `[업체별 + 날짜별]` 2단계로 저장하고 있었다.
날짜 폴더를 일일이 열어야 해서 조회할 때마다 시간이 들었다.

**업체 폴더 한 단계로 줄이고 그 안에 날짜별 엑셀 파일만 두는 구조**로 바꿨다.
파일명에 날짜가 있으면 폴더로 나눌 이유가 없다 — 정렬로 해결되는 것을
디렉터리 계층으로 만들면 탐색 비용만 늘어난다.

## 메일 문의 방식

에러 문의가 기존 메일 스레드에 계속 이어 붙어 히스토리 추적이 안 됐다.
**신규 에러는 새 제목 + 안건 단위로 보내도록** 정리해 검색과 이력 관리가 되게 했다.
