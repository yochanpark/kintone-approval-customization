# 2. 레코드 열람 권한 — 결재선 매트릭스를 권한으로 옮기기

## 문제

편집 잠금([1. 편집 잠금](01-edit-lock.md))을 넣은 뒤 다른 문제가 드러났다.
**다른 사람이 올린 기안까지 목록에 다 보였다.**

요구는 이렇게 정리됐다.

- 기안자는 **자기가 올린 건만** 본다
- 그 건의 승인자·참고자는 결재가 어느 단계로 넘어가든 **끝까지** 본다
- 누가 승인자·참고자인지는 기안자와 **금액(1천만 원 미만 / 이상)**에 따라 다르다 — 엑셀 결재선 매트릭스로 정해져 있다
- 한 사람이 어떤 건에선 기안자, 어떤 건에선 승인자, 또 어떤 건에선 참고자다

## JavaScript로는 안 된다

편집 잠금은 화면에서 동작하는 커스터마이징이다. **누가 레코드를 볼 수 있는지는 서버가 먼저 판단하고,**
JS는 그 뒤에 브라우저에서 실행된다. JS로 목록에서 숨겨도 데이터는 이미 내려왔고 REST API·모바일로 우회된다.
그래서 열람 범위는 Kintone 기본 기능인 **레코드 권한**으로 풀어야 했다.

## 플랫폼 동작 — 설계 전에 확인한 것

| 동작 | 의미 |
|---|---|
| 앱 권한이 1차, 레코드 권한이 2차 | 앱 권한에 없는 사람은 레코드 권한에 넣어도 못 본다 |
| 한 권한 세트 안의 항목은 OR | 하나라도 맞으면 본다 |
| 세트는 위에서부터 **처음 맞는 조건 하나만** 적용 | 넓은 조건이 위에 있으면 아래 세트는 무시된다 |
| 어떤 세트 조건에도 안 걸리는 레코드는 **앱 권한 그대로** | 세트를 일부 기안자만 만들어 두면 나머지 기안자의 건은 그대로 노출 |
| `Created by`·`Assignee`는 그 순간 한 사람만 가리킴 | `Assignee`만 쓰면 이전 승인자는 다음 단계에서 못 본다 |
| 시스템 관리자는 레코드 권한을 무시 | 테스트는 일반 계정으로 |

## 검토한 방법

| 방법 | 장점 | 버린 이유 |
|---|---|---|
| 역할별 사용자 선택 필드(1·2·3차 승인자, 참고자)를 두고 권한에 연결 | 정확, 매트릭스가 바뀌어도 필드 값만 갱신 | **폼에 필드를 추가하지 않는다**는 조건 |
| 처리 담당자(`Assignee`)를 여러 명 동시에 지정 | 필드 추가 없음 | 결재 흐름(프로세스 관리) 자체가 바뀐다 |
| 하나의 "모든 레코드" 세트에 관련자 전원 추가 | 간단 | 1천만 원 이상 건에만 등장하는 승인자가 **관계없는 미만 건까지** 보게 된다 — 처음 문제의 재현 |
| **기안자별 조건부 세트** | 필드·흐름 변경 없음, 매트릭스와 1:1 | 채택 |

## 채택한 구조 — 기안자별 조건부 권한 세트

매트릭스 한 행을 세트 하나로 옮긴다.

```
대상 레코드: 작성자 = [기안자 A]                      (금액 기준으로 명단이 다르면 세트를 둘로 나눔)
  작성자(본인)        보기 · 편집 · 삭제
  1차 승인자          보기 · 편집
  2차 승인자          보기 · 편집
  참고자 1…n          보기
```

- 승인자와 참고자를 다르게 다룰 필요가 없다 — 둘 다 "이 기안자의 건을 볼 사람"이고 차이는 체크박스뿐이다
- 편집 가능 여부의 세부 판정은 기존 편집 잠금 JS가 그대로 맡는다(현재 담당자만 편집)
- 모든 기안자의 세트를 만든 뒤 맨 아래에 대상이 없는 사람용 세트를 두어 **커버되지 않는 레코드가 없게** 한다

## 테스트에서 걸린 것

| 증상 | 원인 |
|---|---|
| 보기만 준 테스트 계정이 다른 사람 기안을 다 봄 | 세트를 기안자 한 명 것만 만든 상태 — 나머지 기안자의 건은 조건에 안 걸려 **앱 권한(전원 보기·편집)**으로 떨어짐 |
| 일부 승인자가 앱을 아예 못 엶 | 앱 권한에 체크가 하나도 없었음 — 레코드 권한 이전에 1차 관문에서 막힘 |
| 세트 안 `작성자` 행이 비어 있음 | 본인이 자기 기안을 못 보게 됨 → 보기·편집·삭제 체크 |
